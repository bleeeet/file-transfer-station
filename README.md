# 文件中转站

一个只做一件事的 macOS 小工具：**把百度网盘当作中转站，在多台电脑、多台服务器之间快速搬文件。**

Apple Silicon，macOS 13 或更新版本。原生 SwiftUI/AppKit，内置 [BaiduPCS-Go](https://github.com/qjfoidnh/BaiduPCS-Go) v4.0.2，无需安装百度网盘官方客户端。

## 为什么要做这个

手上有好几台服务器和电脑，有的在海外，有的在不同城市。它们之间传文件一直很痛苦：

- **SSH / scp / rsync 直传**：跨境、跨运营商的线路带宽很小，大文件动辄几小时，还经常断。
- **远程桌面、远程访问工具**：画面卡，传输更慢，体验很差。
- **百度网盘官方客户端**：会员下载速度确实快，但客户端太重——占内存大、开机常驻、广告和功能一堆，只想传个文件却要背一整套软件。

而百度网盘在国内外都有节点，**开了会员后上传、下载都能跑满本地带宽**。所以思路很简单：

```
电脑 A ──上传(跑满带宽)──▶ 百度网盘 /文件中转站 ──下载(跑满带宽)──▶ 电脑 B
```

两段都走各自到百度的最快线路，绕开 A、B 之间那条又慢又卡的直连。这个应用就是这条链路两端的「轻量客户端」：只有登录、上传、浏览、下载，没有别的。

## 特点

- **轻**：一个约 15 MB 的原生应用，不自启、不后台同步。点窗口左上角的关闭按钮只是关窗口（传输继续进行，点程序坞图标窗口回来），按 ⌘Q 才真正退出。
- **快**：上传、下载单个文件都用 16 线程。实测（东京服务器，SVIP 会员）：

  | 方向 | 单线程 | 多线程 |
  |---|---|---|
  | 下载 | 约 2 MB/s | 16 线程约 34 MB/s |
  | 上传 | 4 线程约 11 MB/s | 16 线程约 22 MB/s |

  非会员账号多线程不生效，速度受百度限速。
- **安全**：不覆盖同名文件、不自动删除任何东西、部分失败不会报告成「完成」；登录凭据不打包、不进日志。
- **自动更新**：每次打开自动检查 GitHub 上的新版本，一键更新。

## 安装

1. 到 [Releases](https://github.com/bleeeet/file-transfer-station/releases/latest) 下载最新的 `FileTransferStation-AppleSilicon-vX.Y.Z.zip`。
2. 解压，把「文件中转站.app」拖进「应用程序」文件夹。
3. 第一次打开时 macOS 可能提示「无法验证开发者」：在 Finder 里**右键 → 打开**，再点「打开」即可（应用为本地签名，没做 Apple 公证）。

之后每次打开都会自动检查更新，有新版会弹窗，点「立即更新」即可，不用再手动下载。

## 使用

1. 打开应用，点右上角「登录账户」（已登录时这里显示「退出登录」），用百度网盘 App 扫窗口里的二维码并在手机上确认；也可改用百度网页登录或账号密码登录，需要验证码时在同一窗口填写。
2. 登录后默认打开网盘里的 `/文件中转站` 文件夹；不存在会自动创建，已有就直接用。顶部可以进入根目录或其他文件夹浏览。
3. **发送**：把本地文件/文件夹拖进窗口，或点「选择文件上传」。所有上传都进入 `/文件中转站`，与当前正在浏览哪个目录无关。
4. **接收**：在另一台电脑上打开应用、登录同一个账号，点右下角的循环箭头刷新。右键选择「下载到…」，或者直接把文件拖到 Finder 里的某个文件夹。
5. 传输时底部显示进度条、已传/总量、速度和剩余时间（多个文件时显示当前文件）。点「详情」可看传输日志。

### 上传的细节

- 文件直接进入 `/文件中转站`，不在网盘建临时文件夹。
- 上传文件夹时，先在网盘里建好同样的目录结构（包括空文件夹）——BaiduPCS-Go 遇到网盘上不存在的目标目录会整批失败，提前建好就能避免。
- 传完后逐个核对文件都在，才报告成功。失败或手动停止时会提示「中转站里可能留有未传完的文件」，并显示传输工具给出的失败原因。
- 网盘里已有同名内容时会停下来让你改名，不会自动覆盖或删除。

### 下载的细节

- 先写进目标目录下的隐藏临时文件夹 `.中转站下载-<任务ID>`，确认任务成功、文件都在之后才挪到目标位置。
- 本地已有同名文件不会被覆盖。
- 失败时临时文件保留，方便排查。

## 登录与隐私

- 登录凭据由 BaiduPCS-Go 保存在 `~/.config/BaiduPCS-Go`（目录权限 700、文件权限 600），不在应用和安装包里，不写进应用日志。如果你本机也装了 BaiduPCS-Go 命令行，两者共享登录状态。
- 扫码登录由应用直接调用百度通行证接口；网页登录用一次性的 WebKit 会话。两种方式都只在内存里持有会话，凭据只通过子进程的输入传给 BaiduPCS-Go，不出现在命令行参数里，也不会进 shell 历史。
- 网页登录只向 `baidu.com` 域导入认证信息。
- 每台设备需要单独登录一次。

## 自动更新

每次启动、每次点右下角的刷新按钮、或手动点右上角「检查更新」时，应用会查询本仓库的[最新 Release](https://github.com/bleeeet/file-transfer-station/releases/latest)：

- 版本号比当前新 → 弹窗显示新版本和更新说明，可选「立即更新」或「以后再说」。
- 点了更新 → 等当前的刷新/传输/登录结束后，下载 zip、核对是同一个应用、替换当前的 `.app` 并自动重启。如果下载完时又有传输在进行，就不打断，下次打开时生效。
- 没网或查询失败 → 自动检查时静默跳过；手动点「检查更新」时会提示「已是最新版本」或「检查失败」。
- 更新提示已经弹出或正在下载时，再点刷新不会重复弹窗。

## 开发与发版（多台电脑协作）

本项目在多台电脑上共同开发，统一推送到这个 GitHub 仓库。

```zsh
./build.sh                 # 构建，产物在 build/文件中转站.app
swiftc -swift-version 5 Sources/Core.swift Tests/main.swift -o /tmp/coretest && /tmp/coretest   # Core 单元测试
```

涉及传输或登录的改动，用 `Tests/mock-cli.py` 做本地集成验证，不用真实账号数据测试。

**发布新版本**（任意一台已 `gh auth login` 的电脑）：

1. `git pull` 拉到最新代码。
2. 改 `Resources/Info.plist` 里的 `CFBundleShortVersionString`（例如 `0.2.0` → `0.3.0`），`CFBundleVersion` 加 1。
3. 提交并推送。
4. 运行 `./release.sh "这次更新了什么"`：自动构建、打包到 `安装包/`，并在 GitHub 创建 `vX.Y.Z` Release、上传 zip。

发布后，其他电脑打开应用就会收到更新提示。

## 项目结构

| 路径 | 内容 |
|---|---|
| `Sources/Core.swift` | 目录解析、传输结果判定、版本号比较等纯逻辑 |
| `Sources/App.swift` | 界面、调用 BaiduPCS-Go 子进程、Finder 拖拽下载、自动更新 |
| `Resources/` | Info.plist、图标、内置 BaiduPCS-Go 及其许可证 |
| `Tests/` | Core 单元测试、集成测试和模拟 CLI |
| `build/` | 构建产物 |
| `安装包/` | 分发用 zip（只含 `.app`，不含登录配置、Cookie、用户文件或测试夹具） |
| `build.sh` / `release.sh` | 构建 / 发版脚本 |

## 验证与限制
