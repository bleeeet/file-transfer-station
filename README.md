# 文件中转站

**把百度网盘当作中转站，在多台电脑、服务器之间快速搬文件的 macOS 小工具。**

- 系统要求：Apple Silicon，macOS 13 或更新
- 原生 SwiftUI/AppKit，约 15 MB，内置 [BaiduPCS-Go](https://github.com/qjfoidnh/BaiduPCS-Go) v4.0.2，不需要装百度网盘官方客户端
- 下载：[最新 Release](https://github.com/bleeeet/file-transfer-station/releases/latest)

## 为什么做这个

如果你的电脑和服务器分散在不同城市甚至海外，互相传文件的常见办法往往都不好用：

| 办法 | 问题 |
|---|---|
| SSH / scp / rsync 直传 | 跨境、跨运营商线路带宽小，大文件要几小时，还常断 |
| 远程桌面 / 远程访问工具 | 画面卡，传输更慢 |
| 百度网盘官方客户端 | 会员速度快，但客户端太重：占内存、开机常驻、广告多 |

百度网盘国内外都有节点，**开会员后上传、下载都能跑满本地带宽**。于是绕开两台机器之间的慢线路：

```
电脑 A ──上传(跑满带宽)──▶ 百度网盘 /文件中转站 ──下载(跑满带宽)──▶ 电脑 B
```

本应用就是这条链路两端的轻量客户端：只有登录、上传、浏览、下载、删除。

## 特点

| | 说明 |
|---|---|
| **轻** | 不自启、不后台同步。关窗口不退出（传输继续，点程序坞图标窗口回来），⌘Q 才退出 |
| **快** | 上传、下载单个文件都用 16 线程（实测见下表） |
| **安全** | 不覆盖同名文件、不自动删除、部分失败不报告成「完成」；登录凭据不打包、不进日志 |
| **自动更新** | 打开时自动检查 GitHub 新版本，一键更新 |

参考速度（一台海外服务器，SVIP 会员；实际速度取决于你的网络和会员等级）：

| 方向 | 少线程 | 16 线程 |
|---|---|---|
| 下载 | 单线程约 2 MB/s | 约 34 MB/s |
| 上传 | 4 线程约 11 MB/s | 约 22 MB/s |

> 非会员账号多线程不生效，速度受百度限速。

## 安装

1. 到 [Releases](https://github.com/bleeeet/file-transfer-station/releases/latest) 下载 `FileTransferStation-AppleSilicon-vX.Y.Z.zip`。
2. 解压，把「文件中转站.app」拖进「应用程序」。
3. 首次打开如提示「无法验证开发者」：在 Finder 里**右键 → 打开**，再点「打开」（应用为本地签名，未做 Apple 公证）。

之后有新版会自动弹窗，点「立即更新」即可。

## 使用

### 1. 登录

点右上角「登录账户」，用百度网盘 App 扫码并在手机上确认。也可以改用百度网页登录或账号密码登录，需要验证码时在同一窗口填写。登录后按钮变为「退出登录」。每台设备要单独登录一次。

### 2. 发送

把本地文件/文件夹拖进窗口，或点「选择文件上传」，也可以在 Finder 里选中后**右键 →「上传到百度云中转站」**（在「快速操作」或「服务」子菜单里；装好后打开一次应用即出现，没出现可注销重新登录一次）。所有上传都进入网盘的 `/文件中转站`（不存在会自动创建，已有就直接用）。

### 3. 接收

在另一台电脑登录同一账号，点右下角循环箭头刷新，然后：

- 选中后点底部「下载…」或右键 →「下载到…」，或
- 直接把文件拖到 Finder 里的某个文件夹。

按住 ⌘ 点选、按住 ⇧ 连选，可一次下载多项。

### 4. 清理

选中后点底部「删除」或右键「删除」，确认后删除（可在百度网盘回收站找回）。

### 5. 查看进度

传输时底部显示进度条、已传/总量、速度和剩余时间（多个文件时显示当前文件）。点「详情」看传输日志。

> 应用只能浏览 `/文件中转站` 及其子文件夹。

## 工作细节

### 上传

- 文件直接进入 `/文件中转站`，不建临时文件夹。
- 上传文件夹时，先在网盘建好同样的目录结构（含空文件夹）。BaiduPCS-Go 遇到不存在的目标目录会整批失败，提前建好可避免。
- 传完逐个核对文件都在才报告成功。失败或手动停止时提示「中转站里可能留有未传完的文件」，并显示失败原因。
- 网盘已有同名内容时停下来让你改名，不覆盖、不删除。

### 下载

- 先写进目标目录下的隐藏临时文件夹 `.中转站下载-<任务ID>`，确认成功、文件齐全后才挪到目标位置。
- 本地已有同名文件不覆盖；多选下载时，只要有一项同名就整批不开始。
- 多选下载逐项进行，某项失败不影响其余项，结束时列出未完成的项目。
- 失败时保留临时文件，方便排查。

### 自动更新

触发时机：每次启动、点右下角刷新、点右上角「检查更新」。查询的是本仓库的[最新 Release](https://github.com/bleeeet/file-transfer-station/releases/latest)。

| 情况 | 行为 |
|---|---|
| 有新版本 | 弹窗显示版本和更新说明，可选「立即更新」或「以后再说」 |
| 点了更新 | 等当前刷新/传输/登录结束 → 下载 zip → 核对是同一个应用 → 替换 `.app` 并自动重启。下载完时又有传输在进行则不打断，下次打开生效 |
| 没网或查询失败 | 自动检查时静默跳过；手动检查时提示「已是最新版本」或「检查失败」 |
| 弹窗已出现或正在下载 | 再点刷新不重复弹窗 |

### 登录与隐私

- 凭据由 BaiduPCS-Go 保存在 `~/.config/BaiduPCS-Go`（目录 700、文件 600），不在应用和安装包里，不写进日志。本机若也装了 BaiduPCS-Go 命令行，两者共享登录状态。
- 扫码登录直接调用百度通行证接口；网页登录用一次性 WebKit 会话。会话只在内存里，凭据只通过子进程输入传给 BaiduPCS-Go，不出现在命令行参数和 shell 历史里。
- 网页登录只向 `baidu.com` 域导入认证信息。

## 已知限制

- 一次处理一批任务。
- 50 GB 级大文件尚未完整实测。
- 与百度接口的兼容性取决于上游 BaiduPCS-Go。

## 开发与发版

### 从源码构建

需要 Apple Silicon Mac 和 Xcode 命令行工具（`xcode-select --install`）。

```zsh
git clone https://github.com/bleeeet/file-transfer-station.git
cd file-transfer-station
./build.sh   # 构建，产物在 build/文件中转站.app
swiftc -swift-version 5 Sources/Core.swift Tests/main.swift -o /tmp/coretest && /tmp/coretest   # Core 单元测试
```

涉及传输或登录的改动，用 `Tests/mock-cli.py` 做本地集成验证，不用真实账号数据。

测试覆盖：目录数量核对、带空格/特殊字符的文件名、部分失败识别、自动建目录、上传发布、下载内容核对、Finder 拖拽下载回调、账号密码/验证码输入、凭据遮蔽、版本号比较。启动、登录界面和自动更新流程已实际检查。

### 发布新版本

需要已安装并登录 GitHub CLI（`gh auth login`），且对仓库有发布权限：

1. 改 `Resources/Info.plist`：`CFBundleShortVersionString` 升版本号，`CFBundleVersion` 加 1。
2. 提交并推送。
3. 运行 `./release.sh "这次更新了什么"`：自动构建、打包到 `安装包/`，在 GitHub 创建 `vX.Y.Z` Release 并上传 zip。

发布后，用户打开应用就会收到更新提示。

> Fork 后自己发版：把 `Sources/App.swift` 里检查更新用的仓库地址（`api.github.com/repos/…/releases/latest`）改成你的仓库，否则应用会去查本仓库的更新。

欢迎提 Issue 和 Pull Request。

### 项目结构

| 路径 | 内容 |
|---|---|
| `Sources/Core.swift` | 目录解析、传输结果判定、版本号比较等纯逻辑 |
| `Sources/App.swift` | 界面、BaiduPCS-Go 子进程调用、Finder 拖拽下载、自动更新 |
| `Resources/` | Info.plist、图标（源文件 `AppIcon.svg`）、内置 BaiduPCS-Go 及其许可证 |
| `Tests/` | Core 单元测试、集成测试、模拟 CLI |
| `build/` | 构建产物 |
| `安装包/` | 分发用 zip（只含 `.app`，不含登录配置、Cookie、用户文件或测试夹具） |
| `build.sh` / `release.sh` | 构建 / 发版脚本 |
